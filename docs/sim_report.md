# 階段 D：系統模擬驗證報告

指令：`bash sim/run.sh`（一個指令完成 產生向量 → 編譯 → 模擬 → 比對）；加 `--vcd 2` 會把第 2 組（random_0）的波形存成 `sim/ns_top.vcd`。

## 結果

- 20 組測試向量（`data/vec_in.hex`、`vec_exp.hex`、`vec_float.npy`、`vec_names.txt`）：全零、單位矩陣、8 組隨機、5 組病態（條件數 1e1～1e5）、小幅值（×0.01）、秩 1、對角、全 1、稀疏。
- **RTL 輸出與位元精確整數模型（`model/fixed_model.py`）20 組、共 1280 個輸出元素，全部逐位元一致。**
- 與 float64 黃金模型的誤差如下表（含 Q4.12 輸入量化與 scale 量化）。隨機矩陣最大誤差約 1e-3～2e-3；病態矩陣因輸入奇異值極小、五輪來不及推到 1，誤差較大，這是演算法與 16 位元格式的特性，不是 RTL 與模型不一致（RTL 與位元精確模型仍然一致）。
- 全零矩陣輸出全為 0（沒有除以零問題，scale 飽和成最大值但 G = 0）。
- 每組從 start 到 done 為 **8527 個週期**（階段 C 估算 8525）。100 MHz 下約 85 µs。
- testbench 交替測試兩種 start 時機（與最後一筆載入同週期、載入結束後 3 個週期），並檢查 start 後 done 立即清除、運算期間 busy 為 1。

## 解讀

- `rank1`、`all_ones` 的輸出奇異值上限只有 0.696：只有一個非零奇異值時，它從 1 出發，係數多項式 3.4445−4.7750+2.0315 = 0.701，五輪後落在約 0.7，這是 Muon 係數的設計行為（float64 黃金模型同樣如此，誤差小於 4e-2）。
- `zeros` 的奇異值全為 0，符合預期。
- 病態矩陣（條件數 ≥ 1e3）輸出的最小奇異值偏低（0.47～0.02），與階段 A 的觀察一致：奇異值太小的方向五輪推不到 0.7。

## 位寬變體（供階段 E 的位寬比較）

`bash sim/run.sh --variant w12`（Q3.9、12 位元）與 `--variant w24`（Q3.19、24 位元）各自產生對應位寬的測試向量（檔名加 `_w12`／`_w24`），RTL 與各自的位元精確模型 20 組全部逐位元一致。w12 對 float64 的誤差較大（隨機矩陣最大 2.3e-2，病態 1e5 最大 0.34），所以對 float64 的誤差上限只對 W ≥ 16 強制，W < 16 以位元一致為通過條件，誤差僅列出。

## 列平行架構

`bash sim/run.sh --arch par`：同一組 20 個測試向量、1280 個輸出元素，與同一份位元精確模型逐位元一致；每組 1,527 個週期（序列式 8,527）。`--variant w12|w24` 與 `--arch par` 可併用，兩個位寬也都一致。

## 測試的有效性

- 各模組的變異測試見 `docs/rtl_design.md`。頂層再做兩個變異：拿掉 done 的遮蔽，testbench 會報「start 後 done 未清除」並抓到錯誤的輸出；
- 拿掉 start 的一拍延遲，testbench **不會**失敗：以目前的管線延遲，最後一筆載入剛好在核心第一次讀取前寫入，這一拍延遲只是額外的時序餘裕，不是功能必要。保留它是為了日後加深載入管線時不會悄悄壞掉。
