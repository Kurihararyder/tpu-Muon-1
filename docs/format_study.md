# 數值格式評估報告（階段 B）

完整數據見 [format_results.md](format_results.md)（由 `model/format_eval.py` 自動產生，重跑即可重現）。

## 1. 假設與評估方法

以下為使用者未指定時採用的**預設假設**，非老師指定：

| 項目 | 假設 |
|---|---|
| 矩陣大小 | 8x8，5 輪 Newton-Schulz |
| 資料位寬 | 16 位元定點（浮點格式僅作比較基準） |
| 縮放 `X = G / (‖G‖F + eps)` | 由外部預先算好；進入資料路徑時量化成儲存格式 |
| 係數 a、b、c | 常數暫存器。定點一律用 Q4.12（因 \|b\| = 4.775 > 4，儲存格式放不下）；浮點用該格式本身 |
| 測試資料 | 20 組標準常態隨機矩陣 + 5 組病態矩陣（條件數 1e1～1e5）+ 零矩陣 + 單位矩陣 |
| 誤差基準 | float64 的 `golden.py`（不是 SVD 精確解；後者本身與演算法輸出就差 0.4～0.8，見階段 A） |

量化規則：
- **浮點**：每次乘法與加法後都量化（含次正規數與飽和）。
- **定點**：資料以 W 位元（F 位小數）儲存；矩陣乘法的乘積進入累加器，每個運算結果寫回儲存格式時才量化一次（含飽和）。
  - 四捨五入：加 0.5 LSB 後捨去。
  - 截斷：直接丟掉低位（二補數下等於 floor，帶負偏差）。
  - 累加器小數位 `accf = min(2F, acc_bits − (整數位 + 3))`；多出的 3 位保護位對應 8 項相加。32 位元時 `accf = 2F`，即乘積不經捨入、完整進入累加器。

## 2. 中間值範圍（決定整數位數）

用 float64 追蹤 25 組輸入、5 輪內各變數的最大絕對值：

| 變數 | 最大絕對值 | 所需整數位（含符號） |
|---|---|---|
| X | 0.895 | 1 |
| A = X·Xᵀ | 1.383 | 2 |
| A·A | 1.948 | 2 |
| B = bA + cA² | 2.737 | **3** |
| B·X | 2.440 | 3 |
| X 新值 | 0.939 | 1 |

`B` 需要 3 個整數位（範圍 ±4），這不只是實測。`B` 的元素絕對值不會超過其譜範數，也就是 `p(λ) = −4.775λ + 2.0315λ²` 在 `λ = σ²` 上的值。只要奇異值 σ ≤ 1.2（即 λ ≤ 1.44），`p` 的最小值約 −2.81（在 λ ≈ 1.175），與實測 2.737 吻合，離 ±4 還有約 1.4 倍餘裕。

**推論：Q2.14（範圍 ±2）必然在 `B` 飽和。** 實測確實如此（見下表），不是實作問題。

## 5. 結論：RTL 預設格式

**選定：資料 Q3.13（16 位元，3 個整數位含符號、13 位小數）、四捨五入、累加器 32 位元（Q6.26，乘積不捨入）、係數 Q4.12。**

理由：
1. **範圍剛好夠用。** 2 個整數位（Q2.14）會讓 `B` 飽和而完全失效；3 個整數位涵蓋最大值 2.74 並留有約 1.4 倍餘裕；Q4.12 多給的 1 個整數位用不到，等於浪費 1 位小數精度。
2. **精度較佳。** 同為 16 位元，Q3.13 的平均誤差約為 Q4.12 的 0.65 倍，病態矩陣最大誤差約為其 0.46 倍。隨機矩陣的最大誤差則兩者相近（Q3.13 為 6.1e-3，Q4.12 為 4.6e-3），差異在雜訊內。
3. **四捨五入優於截斷。** 截斷有系統性偏差，最大誤差約為 2～3 倍；硬體成本只是寫回時多一個常數加法。
4. **比浮點便宜。** 精度優於 bf16（約 40 倍）與 FP16（約 5 倍），且乘加單元為純整數，面積與時序都較浮點單元小。
5. **32 位元累加器、乘積不捨入**可讓 RTL 與 Python 模型逐位元一致（`ns_fix(..., acc_bits=32)`），驗證時不必處理乘積捨入的差異。24 位元的精度相當，列為階段 E 的位寬比較實驗之一。

注意：
- **Q3.13 不在原先指定的候選清單內，是我依範圍分析加入的附加候選。** RTL 會把 W、F 設為參數，若老師要求 Q4.12，只需改 `F = 12`，整數位自動變成 4。
- 係數 a、b、c 無法放進 Q3.13（\|b\| = 4.775 > 4），RTL 需另設 Q4.12 的常數暫存器，乘法器兩輸入位寬為 16 × 16。

## 6. 限制

- 測試資料是常態隨機與人造病態矩陣，未涵蓋真實訓練梯度的分布。
- 範圍分析以 8x8 為準；矩陣放大後 `A` 的元素與累加項數變多，需重新檢查整數位。
- 累加器的中間部分和溢位未單獨模擬（二補數環繞下，只要最終和不溢位結果仍正確）；只檢查了每次累加的最終值。
- 結果只代表格式的相對優劣；絕對的面積、功耗仍要等階段 E 合成。
